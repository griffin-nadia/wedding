## Decisions made (and why)

- **Controls live on the experiment page, not the index.** The phone page (lab-play.html) is what Jehan opens on a
  phone, so the Options sheet and Compare with live are there; the laptop viewer frames that same page and mirrors its
  address. One set of controls, nothing to keep in step.
- **Icon-only floating buttons** (Compare with live, Options) at the lower right: labelled buttons covered the content
  being judged. Each has an accessible name and a tooltip; Compare with live is a toggle button (aria-pressed) whose
  name never changes.
- **The site's own Sheet** for Options (focus trapped, Escape closes, focus returns), not a hand-made dialog.
- **Takes as native radios** in the sheet: the segmented control ran off a 390 phone with three long labels.
- **Copy settings falls back to a selected text box** when the clipboard isn't allowed (it isn't in a headless
  browser, or on some phones over plain http).
- **Reference cards are the live pages** (with the sample household), not copies, so they can't drift.
- **Photos on in the lab** (PUBLIC_PHOTOS=1 in lab-serve.mjs): they're public since 4 Oct and committed; the lab should
  show the real prints.
- **Whole-page experiments are marked `bare`** per entry (not per area), so component experiments sit in the real site
  shell with the real tokens.
- **The badge shows the worst take**, so nothing looks better than it is; every take is in perf.json.
- **Gzipped static server inside lab-perf.mjs**, so transfer sizes match GitHub Pages (vite preview doesn't compress).
- **Baselines for anything that looks bad:** the globe against the site's own globe (headless draws WebGL in software,
  so absolute fps means little); the sweep against the same theme change with the sweep off.
- **The arrival framing measures the live site in frames**, not a model of it. The first version modelled the old
  centred crop and found the envelope over their faces at 360 and 390 wide; by the time it was measured, #178 had
  fixed it, so the experiment now measures whatever is live and the Ready to ship is a test that keeps it fixed.
- **The loading screen only after 350 ms**, never holding anything back; the song is warmed only on 4G or wifi
  without Save-Data. The measurements say the background warm is the real gain; the screen itself is Jehan's call.
- **Stand-ins are labelled as stand-ins:** the lab's arrow, the polaroid hand (the display face, not handwriting).
- **No new dependencies.** QR in the terminal uses qrcode-generator (already the site's).
